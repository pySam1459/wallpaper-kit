# Library and adapter integration

## Status

The public blank/motion/page API and native/headless consumers are implemented; use [blank verification](blank-renderer.md), [diagnostic motion](diagnostic-motion.md) and [TEX page drawing](texture-pages.md). A native consumer imports immutable frames on a separate same-adapter D3D11 device. Local Windows Zed/GPUI diagnostic and T3/Electron scene-image adapters have verified host composition. T3 displays clear new-chat and blurred conversation backgrounds; full scene fidelity and host performance acceptance remain unverified. C ABI and WebView2 adapters remain planned.

## Consumer outcome

An application embeds the renderer through a small contract without acquiring a dependency on the example viewer. Each adapter displays frames and handles ownership, synchronization, resizing, visibility, and shutdown correctly.

## How to reach it

The prepared local Codex demo opens with the root `Launch Codex Wallpaper.cmd` or `pwsh -File integrations/launch-codex.ps1`. Missing/stale adapter builds are automatic; a ready demo is reused and brought forward. `-Restart` reopens the owned pair and `-Rebuild` forces a build. `pwsh -File integrations/verify-codex-launch.ps1` verifies the CMD route from another working directory, process reuse/restart, connected wallpaper readiness and preservation of saved settings/sign-in. See `artifacts/codex-re/launch-report.json` and [the launch guide](../../../../docs/research/codex-wallpaper-demo.md#run-and-stop). Local prerequisites and the inspected app-version pin still apply.

The examples consume the public library API. Each framework adapter needs its own minimal real host and verified route. Record those routes separately when implemented.

The ignored local Zed experiment is documented in [integrations/zed.md](../../../../integrations/zed.md). Its fork is pinned to `96984225abc235519e66b5c6c9ed23b87621f868`. Run `pwsh -File integrations/verify-zed.ps1` from the repository root to exercise the shared adapter in a native GPUI consumer. Run `pwsh -File integrations/launch-zed.ps1` to open the built editor with its isolated profile. In Zed Settings, search for “Animated Chat Background”; the Windows toggle writes `agent.wallpaper_enabled`. These local files are available only while the ignored experiment is retained.

## Drive and observe

Enable Settings > Appearance > Animated chat background. A new draft shows clear scene images; a started thread shows the same background blurred and darkened. The local fixture route verifies appearance without contacting a provider.

Load the scene, present its frames behind host content, and exercise the affected adapter's size, DPI, playback, visibility, and shutdown behavior. Keep host input working while animation runs. Verify texture synchronization and release with graphics diagnostics where available. Evaluate CPU frame copies or GPU transfers through measurements rather than assuming that a handle implies efficient sharing.

## Evidence and limits

The 2026-10-11 Codex resolution revision requests 3840 × 2160 native output and preserves that size through shared-texture import, canvas capture and decoded video. After `integrations/build-codex.ps1` and `launch-codex.ps1`, run `node integrations/codex-demo/verify-resolution.cjs`. `artifacts/codex-re/4k/report.json` verifies default 1080p compatibility, 4K native frames, three retained leases, invalid-size rejection and actual 4K WebRTC decoder dimensions. `received-video.png` retains the decoded 4K frame and `codex.png` captures the app. The Appearance verification also checks 4K video alongside its settings flow. The blurred conversation uses validated isolated projection fixtures, not a submitted provider run. These checks do not establish full authored scene compatibility, smooth display cadence, provider submission, minimized-window behavior, light-theme readability or measured input/scroll latency. The core renderer was unchanged during this integration detour.

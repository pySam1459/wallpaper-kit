# Diagnostic image composition

The library places cropped TEX images on an orthographic canvas and blends them in submission order on Direct3D 11. The selected-object snapshot route reads actual scene/model/material JSON and preserves supported 2D geometry. This is an intermediate stage-3 component, not full scene loading or playback.

## Public consumer path

Create an `ImageLayer` from an `Arc<TextureRegion>`, centre, displayed size, counterclockwise rotation in degrees, opacity and brightness. Canvas Y increases upward; source rows increase downward. Construct `ImageComposition::new(canvas, layers)` in back-to-front order, then enqueue its Arc with `Renderer::render_images`. Take a completed frame through the existing nonblocking API. `Frame::image_layer_count` identifies this content without retaining CPU pixels. The canvas stretches to the output dimensions; resize preserves the selected composition.

Point sampling clamps each draw inside its source rectangle, including BC3 crops beginning inside blocks. RGB is multiplied by brightness and clamped for SDR blending. Source alpha is multiplied by opacity; straight-alpha blending accumulates over `BLANK_RGBA`, preserving opaque output alpha. These are diagnostic code-value conventions. Filtering, color management and Wallpaper Engine material fidelity need reference comparison. The [official layer reference](https://docs.wallpaperengine.io/en/scene/scenescript/reference/class/ILayer.html) describes origin, degree rotation and relative scale; D3D11 defines [separate RGB and alpha blend state](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_render_target_blend_desc).

At most 32 draws and 256 MiB of unique page payloads are admitted. Repeated page Arcs share one upload and count once. The worker evicts obsolete sources after preceding GPU completion and before uploading replacements. `source_texture_bytes` and `texture_uploads` report sources separately from the three-output pool. The cap excludes consumer textures, driver overhead, decoding temporaries and caller-retained content; it is not a total process or GPU memory budget. Constructing descriptors/enqueueing does no file I/O or decoding. Shader compilation and uploads run on the render worker.

## Selected-object preparation

`TextureDecoder::image_snapshot(&object_ids, sprite_frame_index)` performs blocking JSON I/O and serial page decoding. Call it on a tool or asset worker. It returns an `ImageSnapshot` containing the composition, drawn IDs in authored order and explicit omissions. Each sprite uses the supplied frame index; static textures use page zero. This route has no time, cache, prefetch or playback state. Geometry/appearance and unique decoded page sizes are checked before payload allocation. Shared asset/page references reuse a CPU page. Page metadata and payload are read through the same checked handle for admission.

The supported profile is scene version 5, positive 2D size/XY scale, zero origin Z and zero X/Y rotation, and an autosized image model with one `genericimage4` translucent, depth-disabled material pass. Its combinations are empty or `SPRITESHEET=1`; it has one texture. Selected unknown fields, scripts, nonzero crop offsets, unsupported materials, missing IDs and malformed inputs fail with context. Effects, parallax, general camera/color settings and unselected objects are explicitly omitted. This function does not inspect a complete dependency graph or prove compatibility with all scenes sharing that shader name.

Target selections `[28,32,77,86]` draw background, clouds, foreground and character. `[72,89]` isolates both bird instances with one shared page. Combining background and a full bird atlas exceeds this slice's 256 MiB source cap and fails before bird payload decoding. [Sprite extraction](sprite-extraction.md) now supplies smaller frame regions separately; this snapshot loader still uses whole atlases. Object 22 (`Fils`) has a nonzero model crop offset whose semantics remain unresolved; selection fails explicitly. Effects, particles, light shafts, chromatic aberration, parallax and full-scene fidelity remain open.

## Verification

```powershell
cargo run --locked --example native-viewer -- --layers-fixture
pwsh -File ./scripts/verify.ps1
pwsh -File ./scripts/verify.ps1 -Software -SkipNative
```

The existing `texture-checks` consumer now adds a four-layer generated composition. An independent CPU inverse-transform oracle checks every captured pixel, with at most two RGB code values of UNORM blend tolerance and exact opaque alpha. The fixture exercises crops, RGBA/R8/BC3, 90/180-degree rotation, overlap, off-canvas clipping, opacity and brightness above one. Geometry and texel boundaries avoid exact pixel-centre ties. Arbitrary-angle edge coverage remains subject to D3D rasterization precision; this cardinal fixture is not an arbitrary-angle edge oracle. A reversed-order draw must fail the oracle. Public tests also check early invalid geometry/appearance rejection, descriptor limits, shared snapshot pages and source admission before a deliberately corrupt oversized PNG.

Native `--layers-fixture` prepares assets before window creation. `verify-native.ps1 -LayersFixture` checks independent-device back-buffer captures at initial and resized dimensions, idle presentation, switching to motion and owned-process exit. The full gate runs a separate composition instance. Pass paired scene/engine roots as described in [TEX verification](texture-pages.md) to add two actual target snapshots and explicit budget/crop-offset rejections. `textures/report.json` records selections, sprite frame index, omissions, preparation duration, source counters and package identity. Inspect the captures; successful builds alone are insufficient. Preparation timings exclude upload/capture and are not host latency or steady rendering measurements.

The [hardware/native receipt](../artifacts/20261010-143654-e7284f61/manifest.json) and [WARP/headless receipt](../artifacts/20261010-143801-ce59e160/manifest.json) passed on 10 October 2026 with Rust 1.91 and Windows x64. Hardware used an NVIDIA GeForce RTX 5080; WARP explicitly skipped native scenarios and proprietary content. All 41 tests and the required formatting, Clippy, Rustdoc, dependency and consumer checks passed. Native composition capture, resize, idle and owned exit passed. Doctor accepts the matching diagnostic receipt and still rejects full scene readiness with `-ScenePath`.

The hardware target snapshots at 960x540 used 131,622,276 source payload bytes for four images and 248,832,000 for both bird instances sharing a page. Preparation took roughly 1.6 seconds and 1 second respectively in an earlier matching-code debug run, excluding upload/capture; these are diagnostic observations, not performance acceptance. The four-image capture shows the sky, clouds, foreground and character. The isolated frame-239 bird capture shows a small bird near the right edge; frame zero was transparent. Missing effects, crop-offset placement and other omissions prevent a complete target composition. No Wallpaper Engine reference comparison, live sprite playback, GPU timing or host latency has been verified. Ignored evidence may be absent in other checkouts; rerun there.

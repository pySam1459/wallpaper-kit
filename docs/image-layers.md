# Diagnostic image composition

The library places cropped TEX images on an orthographic canvas and blends them in submission order on Direct3D 11. The selected-object snapshot route reads actual scene/model/material JSON and preserves supported 2D geometry. This is an intermediate stage-3 component, not full scene loading or playback.

## Public consumer path

Create an `ImageLayer` from an `Arc<TextureRegion>`, centre, displayed size, counterclockwise rotation in degrees, opacity and brightness. Canvas Y increases upward; source rows increase downward. Construct `ImageComposition::new(canvas, layers)` in back-to-front order, then enqueue its Arc with `Renderer::render_images`. Take a completed frame through the existing nonblocking API. `Frame::image_layer_count` identifies this content without retaining CPU pixels. The canvas stretches to the output dimensions; resize preserves the selected composition.

Point sampling clamps each draw inside its source rectangle, including BC3 crops beginning inside blocks. RGB is multiplied by brightness and clamped for SDR blending. Source alpha is multiplied by opacity; straight-alpha blending accumulates over `BLANK_RGBA`, preserving opaque output alpha. These are diagnostic code-value conventions. Filtering, color management and Wallpaper Engine material fidelity need reference comparison. The [official layer reference](https://docs.wallpaperengine.io/en/scene/scenescript/reference/class/ILayer.html) describes origin, degree rotation and relative scale; D3D11 defines [separate RGB and alpha blend state](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_render_target_blend_desc).

At most 32 draws and 256 MiB of unique page payloads are admitted. Repeated page Arcs share one upload and count once. The worker evicts obsolete sources after preceding GPU completion and before uploading replacements. `source_texture_bytes` and `texture_uploads` report sources separately from the three-output pool. The cap excludes consumer textures, driver overhead, decoding temporaries and caller-retained content; it is not a total process or GPU memory budget. Constructing descriptors/enqueueing does no file I/O or decoding. Shader compilation and uploads run on the render worker.

`ImageLayer::with_blur(GaussianBlur)` adds optional source-space Gaussian filtering and a red-channel mask before composition. [Gaussian blur](gaussian-blur.md) defines the kernel, alpha/mask semantics, scratch admission and verification. Masks join the unique-page budget; scratch has a separate 128 MiB payload cap and `effect_texture_bytes` counter. `with_precise_blur(PreciseBlur)` selects the separate [checked Wallpaper Engine profile](precise-blur.md); each operation replaces the prior effect. `with_cloud_motion(CloudMotion, Duration)` selects [noise displacement](cloud-motion.md), including an optional mask and an explicit sample time.

## Selected-object preparation

`TextureDecoder::image_snapshot(&object_ids, sprite_frame_index)` performs blocking JSON I/O and serial page decoding. Call it on a tool or asset worker. It returns an `ImageSnapshot` containing the composition, drawn IDs in authored order and explicit omissions. Each sprite uses the supplied frame index; static textures use page zero. Cloud motion uses time zero. This route has no running clock, cache, prefetch or playback state. Geometry/appearance and unique decoded page sizes are checked before payload allocation. Shared asset/page references reuse a CPU page. Page metadata and payload are read through the same checked handle for admission.

The supported profile is scene version 5, positive 2D size/XY scale, zero origin Z and zero X/Y rotation, and an autosized image model with one `genericimage4` translucent, depth-disabled material pass. Its combinations are empty or `SPRITESHEET=1`; it has one texture. Static crop offsets are validated as finite two-component metadata; placement uses the authored origin and size. Selected unknown fields, scripts, nonzero animated crop offsets, unsupported materials, missing IDs and malformed inputs fail with context. The checked precise-blur and cloud-motion profiles are applied; other effects, parallax, general camera/color settings and unselected objects are explicitly omitted. This function does not inspect a complete dependency graph or prove compatibility with all scenes sharing that shader name.

Target selections `[28,32,77,86]` draw background, clouds, foreground and character. `[72,89]` isolates both bird instances with one shared page. `[22]` draws the cropped wire image. Combining background and a full bird atlas exceeds this slice's 256 MiB source cap and fails before bird payload decoding. [Sprite extraction](sprite-extraction.md) supplies smaller frame regions for [combined playback](image-playback.md); this snapshot loader still uses whole atlases. The first bird and wires use authored precise blur. Particles, light shafts, chromatic aberration, parallax and full-scene fidelity remain open.

### Static import cropping

[Wallpaper Engine's texture documentation](https://docs.wallpaperengine.io/en/scene/performance/texture.html) says that importing cropped image layers also adjusts their position to compensate for the removed space. For this checked static profile, we therefore use the stored layer position and size directly. Applying model `cropoffset` a second time would shift the image again. It is not a source-pixel crop request; the TEX page already contains the cropped pixels. This is an interpretation of documented import behavior and the target data, rather than a specification of every model's crop semantics.

The target wire model has `cropoffset = 0 -736.5`, a 3840x687 page, authored origin `1925.17834 458.90564`, and scale `1.01630`. Its offset magnitude equals half the removed height from a 2160-pixel image. The authored position places the wire strip near the bottom of the scene. The native capture was visually checked against the locally installed preview GIF for that placement; its effects and parallax remain omitted. A preview comparison is not live Wallpaper Engine fidelity evidence.

Generated contracts check that nonzero static offsets preserve position, size, rotation and the full source region in both snapshots and playback. Invalid vector shapes, types and nonfinite values fail before a deliberately corrupt PNG can decode. The combined native fixture also carries nonzero static crop metadata; its independent pixel oracle catches an extra transform or pixel crop.

## Verification

```powershell
cargo run --locked --example native-viewer -- --layers-fixture
pwsh -File ./scripts/verify.ps1
pwsh -File ./scripts/verify.ps1 -Software -SkipNative
```

The existing `texture-checks` consumer adds a six-layer generated composition. An independent CPU inverse-transform oracle checks every captured pixel, with at most two RGB code values of UNORM blend tolerance and exact opaque alpha. The fixture exercises crops, RGBA/R8/BC3, masked Gaussian blur, horizontal blur, [precise blur](precise-blur.md), [cloud motion](cloud-motion.md), 90/180-degree rotation, overlap, off-canvas clipping, opacity and brightness above one. Gaussian's oracle uses direct two-dimensional f64 convolution; precise blur expands paired samples into integer CPU taps with byte quantization between axes. Geometry and texel boundaries avoid exact pixel-centre ties. Arbitrary-angle edge coverage remains subject to D3D rasterization precision; this cardinal fixture is not an arbitrary-angle edge oracle. Reversed-order and missing-blur draws must fail the oracle. Public tests also check early invalid geometry/appearance rejection, descriptor limits, shared snapshot pages and source admission before a deliberately corrupt oversized PNG.

Native `--layers-fixture` prepares assets before window creation. `verify-native.ps1 -LayersFixture` checks independent-device back-buffer captures at initial and resized dimensions, idle presentation, switching to motion and owned-process exit. The full gate runs a separate composition instance. Pass paired scene/engine roots as described in [TEX verification](texture-pages.md) to add three actual target snapshots, including wires, and an explicit source-budget rejection. `textures/report.json` records selections, sprite frame index, omissions, preparation duration, source counters and package identity. Inspect the captures; successful builds alone are insufficient. Preparation timings exclude upload/capture and are not host latency or steady rendering measurements.
